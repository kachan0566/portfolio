## 2. 概要

糸価格登録画面から、糸と対象年月を指定して単価を保存する。

このエンドポイントは外部システム向けのJSON APIではなく、ログイン済みの利用者がブラウザから使用するWebフォーム専用処理である。

同じ糸・年月の価格がすでに存在する場合は、既存価格を新しい価格で上書きする。

## 3. 利用権限

- ログインが必要
- 登録できる利用者は以下に限定する
  - 管理者
  - 購買担当者
- その他の利用者は登録できない
- 通信はHTTPSを使用する
- LaravelのセッションCookieとCSRF対策を使用する



## 4. 認証

- 認証方式はLaravel標準のセッション認証とする
- 価格登録の実行にはログイン済みセッションCookieが必要
- フォーム送信時は有効なCSRFトークン（`_token`）を必須とする
- 未ログインの利用者は`302`でログイン画面へ遷移させる
- 認証済みでも権限不足の場合は`403 Forbidden`を返す



## 5. エンドポイント


| 項目       | 内容                                  |
| -------- | ----------------------------------- |
| URL      | `/prices`                           |
| HTTPメソッド | `POST`                              |
| ルート名     | `prices.store`                      |
| 用途       | 糸価格の新規登録または上書き                      |
| 送信形式     | `application/x-www-form-urlencoded` |
| 文字コード    | UTF-8                               |
| 応答形式     | HTML画面へのリダイレクト                      |
| JSON対応   | 対応しない                               |




### 関連画面


| 画面    | URL                        |
| ----- | -------------------------- |
| 糸価格一覧 | `GET /prices`              |
| 糸価格登録 | `GET /prices/create`       |
| 糸価格編集 | `GET /prices/{price}/edit` |




## 6. リクエスト



### パスパラメータ

なし。

### クエリパラメータ

なし。

### フォーム項目


| 名前            | 型   | 必須  | 制約                     | 説明             |
| ------------- | --- | --- | ---------------------- | -------------- |
| `_token`      | 文字列 | はい  | 有効なCSRFトークン            | 不正送信を防ぐためのトークン |
| `material_id` | 整数  | はい  | 登録可能な糸マスタに存在するID       | 対象となる糸のID      |
| `ym`          | 文字列 | はい  | `YYYY-MM`形式かつ日本時間の当月以降 | 価格の対象年月        |
| `price`       | 整数  | はい  | 1～9,999,999            | 単価（円/kg）       |




### 入力例

```http
POST /prices HTTP/1.1
Content-Type: application/x-www-form-urlencoded
Cookie: セッションCookie

_token=CSRFトークン
&material_id=5
&ym=2026-08
&price=1850
```



## 7. 入力チェック



### material_id

以下の場合はエラーとする。

- 未入力
- 整数ではない
- 糸マスタに存在しない
- 生機、製品、染料など、糸以外の材料ID
- 登録対象として無効化されている糸



### ym

以下の場合はエラーとする。

- 未入力
- `YYYY-MM`形式ではない
- 実在しない年月
- 日本時間における当月より前

例として、現在が2026年7月の場合は次のようになる。

- `2026-07`：登録可能
- `2026-08`：登録可能
- `2026-06`：登録不可
- `2026/07`：登録不可
- `202607`：登録不可
- `2026-13`：登録不可

未来年月の上限は設けない。

### price

以下の場合はエラーとする。

- 未入力
- 整数ではない
- 0以下
- 9,999,999を超える
- 小数
- 数値以外の文字列



## 8. 保存処理

入力チェックの完了後、`material_id`と`ym`の組み合わせで既存価格を確認する。

### 新規登録

同じ糸・年月の価格が存在しない場合、次の内容を登録する。


| 保存項目          | 保存値                 |
| ------------- | ------------------- |
| `material_id` | リクエストの`material_id` |
| `ym`          | リクエストの`ym`          |
| `unit_price`  | リクエストの`price`       |
| 登録日時          | サーバーが設定する現在日時       |


画面から送られる`price`は、DBでは`unit_price`として保存する。

### 上書き

同じ糸・年月の価格が存在する場合、既存レコードの`unit_price`を新しい価格で上書きする。

新しいレコードは追加せず、`material_id`と`ym`の組み合わせにつき1件だけ保持する。

### 同時送信・二重送信

- 二重送信されても価格マスタは1件だけ保持する
- 複数の更新が同時に行われた場合、最後に正常完了した更新を有効とする
- すべての正常な登録・更新操作を操作履歴へ記録する

複数の更新処理が同時に実行された場合は、最後にDBトランザクションのコミットが完了した更新内容を有効とする。価格の更新前値と操作履歴の整合性を保つため、更新対象のレコードを排他制御したうえで価格と履歴を同一トランザクション内に保存する。

## 9. 操作履歴

価格マスタとは別に、次の履歴を保存する。


| 項目    | 内容                |
| ----- | ----------------- |
| 操作者   | 登録・更新を行った利用者ID    |
| 操作種別  | 新規登録または更新         |
| 糸ID   | 対象の`material_id`  |
| 対象年月  | 対象の`ym`           |
| 更新前価格 | 新規登録時は空、更新時は変更前価格 |
| 更新後価格 | リクエストで指定された価格     |
| 操作日時  | 日本時間での操作日時        |


価格の保存と履歴の保存は、両方が成功した場合だけ完了とする。

履歴保存に失敗した場合は価格も保存せず、処理全体を取り消す。

二重クリック防止と一意なリクエストIDを使い、同一送信は1回だけ処理する

## 10. 成功時のレスポンス



### 新規登録時


| 項目         | 内容            |
| ---------- | ------------- |
| ステータスコード   | `302 Found`   |
| 遷移先        | `GET /prices` |
| フラッシュメッセージ | `糸価格を登録しました。` |




### 上書き時


| 項目         | 内容            |
| ---------- | ------------- |
| ステータスコード   | `302 Found`   |
| 遷移先        | `GET /prices` |
| フラッシュメッセージ | `糸価格を更新しました。` |


ブラウザは`Location`ヘッダーに従って一覧画面へ移動する。

一覧画面の表示に成功した場合は、最終的に`200 OK`のHTMLが返る。

## 11. エラー時のレスポンス



### 入力エラー


| 項目       | 内容                   |
| -------- | -------------------- |
| ステータスコード | `302 Found`          |
| 遷移先      | 糸価格登録画面              |
| セッション    | `errors`と入力値`old`を保存 |
| 保存処理     | 実行しない                |


パスワードやCSRFトークンなど、安全上保持すべきでない値は`old`へ保存しない。

### その他のエラー


| 状況              | ステータス・動作                    |
| --------------- | --------------------------- |
| 未ログイン           | `302`でログイン画面へ移動             |
| 権限不足            | `403 Forbidden`             |
| CSRFトークン不正・期限切れ | `419 Page Expired`          |
| 対応していないHTTPメソッド | `405 Method Not Allowed`    |
| 保存処理・履歴保存の失敗    | `500 Internal Server Error` |


本番環境では、500エラーの詳しい内部情報やプログラムのエラー内容を画面へ表示しない。

## 12. セキュリティ要件

- HTTPSを必須とする
- セッションCookieには`Secure`と`HttpOnly`を設定する
- CSRFトークンを必須とする
- サーバー側で認証と権限確認を行う
- 画面側の入力制限だけに依存しない
- エラーログへCSRFトークンやセッションIDを記録しない
- 利用者から送られた値をそのままHTMLへ表示しない



## 13. 保存先

本番環境ではDBの`material_prices`テーブルへ保存する。

`material_id`と`ym`の組み合わせには一意制約を設定し、同じ組み合わせのレコードが複数作成されないようにする。

デモ環境のセッション保存処理は本番仕様の対象外とする。

## 14. 障害時の扱い

- 成功メッセージが表示された場合のみ、保存完了として扱う
- 500エラーになった場合、価格と操作履歴の両方を保存しない
- 利用者は一覧画面で保存結果を確認する
- 不明な場合は、再登録前に一覧画面の価格を確認する
- サーバー側では、操作者、対象の糸・年月、発生日時を調査できるログを残す



## 15. スコープ外

この処理では次の操作を行わない。

- 糸以外の材料価格登録
- 外部システムからのJSON登録
- 既存価格の削除
- 為替換算
- 税計算
- kg以外の単位への変換
- 原価の再計算処理
- 過去月価格の登録・更新

## 17. 受け入れテスト

本番リリース前に、最低限次を確認する。

- 管理者が新規価格を登録できる
- 購買担当者が新規価格を登録できる
- その他の利用者は登録できない
- 未ログイン状態では登録できない
- 同じ糸・年月を送信すると既存価格が上書きされる
- 新規登録と更新でメッセージが変わる
- 過去月を登録できない
- 当月と未来月を登録できる
- 価格の下限・上限が機能する
- 糸以外の材料IDを登録できない
- CSRFトークンがない場合は419になる
- 二重送信でも価格マスタが重複しない
- 登録者と更新前後の価格が履歴へ残る
- 履歴保存に失敗した場合、価格も保存されない
- 500エラーで内部情報が画面に表示されない



## 18. 現在の実装との差分

この仕様は次回本番リリース向けの目標仕様であり、現在の実装とは次の差がある。

- 現在はログイン・権限制御が設定されていない
- 現在の単価チェックには9,999,999の上限がない
- 現在は過去月も登録できる
- 現在は重複する糸・年月を入力エラーとして拒否している
- 現在は登録者と価格変更履歴を保存していない
- 現在は価格保存と履歴保存をまとめた処理がない
- 現在の完了メッセージは新規登録用のみ
- デモ環境ではDBではなくセッションへ保存される場合がある

したがって、この仕様書を本番仕様として承認する前に、実装とテストを仕様へ合わせる必要がある。
